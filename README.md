# ShadowHunt Pro

Real-world multiplayer GPS manhunt — an installable PWA (Android, iOS, desktop). Hunters close in on
server-generated, blurred location pings while a shrinking zone forces Shadows to move.

**Stack:** React 18 + TypeScript + Vite · Tailwind CSS v4 · Supabase (Postgres, Auth, Realtime) · MapLibre GL + OpenStreetMap · vite-plugin-pwa

## Features
- **5 modes:** Classic Hunt, Battle Royale, Team vs Team, Infection, Last Shadow Standing
- Room codes, passwords, public matchmaking / quick match, spectators, rematch
- Host lobby (teams, kick, transfer host, live settings), desktop **host dashboard** (roster, disputes, anomalies, live stats, pause/abort)
- Configurable head start, duration, reveal interval & blur, GPS interval, tag radius, player cap
- Stepped or continuous **shrinking zone** that can also **move** to a random final position, out-of-zone grace/elimination
- Custom **arena maps**: polygon play-area **boundaries** (out of bounds = outside the zone) and safe zones
- Live map + tactical compass, proximity bands (never coordinates), haptics, screen wake lock
- Tag → target confirm/dispute → host ruling; automatic win detection per mode
- XP, 8 ranks, 13 achievements, profiles, match history, global leaderboard, **tournaments** with standings
- **Replays** (animated tracks) and match analytics
- Optional team **voice chat** (WebRTC mesh, signalled over Realtime; TURN credentials via `VITE_ICE_SERVERS_JSON`)
- **Push notifications** (Web Push) for reveals, hunt start, tags, SOS and match end — works with the app in the background
- **SOS** emergency stop (pauses everyone, freezes timers & zone), consent + traffic-safety briefing

## Security model
- All mutations are `SECURITY DEFINER` RPCs that validate everything (membership, phase, team, distance, freshness). Clients have **read-only** table access through RLS.
- Exact positions are readable only by yourself and your own team (plus a non-playing referee pinned at match start). Opponents see only blurred `reveals` generated by the server on schedule; the true position is always inside the blur circle, never at its centre.
- Room passwords are bcrypt-hashed in a table no client can read.
- GPS anti-cheat: per-update speed/teleport heuristics, suspect fixes can't tag, flags surface to the host. **It is not foolproof** — GPS drift causes false positives and careful spoofers can evade it.
- Privacy: live positions deleted at match end; replay tracks purged after 48 h (`purge_location_history`, auto-scheduled if `pg_cron` is enabled); users can wipe their history any time.
- Voice signalling uses a public Realtime broadcast channel; media is peer-to-peer DTLS-SRTP.

## Setup
1. Create a Supabase project. In **Auth → Providers** enable **Anonymous sign-ins** (guest play) and Email (magic links). Add your site URL to the redirect allow-list.
2. Apply the migrations: `npx supabase link --project-ref <ref> && npx supabase db push` (or paste `supabase/migrations/*.sql` into the SQL editor, in order). Optionally enable the `pg_cron` extension first for automatic data purging.
3. `cp .env.example .env` and fill `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`.
4. `npm install && npm run dev`

### Push notifications (optional)
1. `npx web-push generate-vapid-keys` → put the public key in `VITE_VAPID_PUBLIC_KEY`.
2. Enable the `pg_net` extension. Deploy the function: `npx supabase functions deploy push --no-verify-jwt`.
3. `npx supabase secrets set PUSH_WEBHOOK_SECRET=<random> VAPID_PUBLIC_KEY=… VAPID_PRIVATE_KEY=… VAPID_SUBJECT=mailto:you@example.com`
4. In the SQL editor: `insert into private.app_config values ('push_url','https://<ref>.supabase.co/functions/v1/push'), ('push_secret','<same random>') on conflict (key) do update set value = excluded.value;`
5. Players enable **Match alerts** on their profile (iOS: install to the home screen first). Notifications never contain coordinates.

Deploy `dist/` anywhere static (`npm run build`; SPA fallbacks included for Netlify, Vercel and GitHub Pages — see `.github/workflows/deploy-pages.yml`). Geolocation requires HTTPS.

## Mobile apps (Android & iOS)
The same codebase ships as native apps via **Capacitor** (`android/`, `ios/`, `capacitor.config.ts`). Native-only extras (`src/lib/native.ts`):
background GPS that keeps working with the screen off (Android foreground service / iOS location background mode),
location uploads over the native HTTP stack (immune to Android's WebView background throttling), real haptics on iOS,
keep-awake, local notifications for reveals/tags/SOS while backgrounded, mock-location detection on Android
(device-reported hint → host anomaly list), and email sign-in deep links (`io.github.jeeveshpatil.shadowhunt://auth-callback`).

**Get the Android app:** download https://github.com/jeeveshpatil/skills-github-pages/releases/download/android-latest/ShadowHuntPro.apk (or tap "Get the Android app" on the website); every build of `main` refreshes it. Open the APK
on your phone and allow "install unknown apps". For a signed release / Play Store AAB add repo secrets
`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`
(create a keystore with `keytool -genkeypair -v -keystore release.jks -alias shadowhunt -keyalg RSA -keysize 2048 -validity 10000`,
then `base64 -w0 release.jks`).

**iOS:** CI compiles the project for the simulator. To run on an iPhone you need a Mac with Xcode: `npm ci && npm run ios`,
pick your Apple ID team under *Signing & Capabilities*, and run. TestFlight/App Store needs an Apple Developer account.

**Local dev:** `npm run android` / `npm run ios` (builds web, syncs, opens Android Studio / Xcode). Regenerate icons with `npm run assets:generate`.

Supabase: add `io.github.jeeveshpatil.shadowhunt://auth-callback` under *Authentication → URL Configuration → Redirect URLs* for email sign-in in the apps.
